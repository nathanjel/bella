# Migration report: CPython 3.14.8 to 3.15.2

On 2026-11-01 the reference moved from CPython 3.14.8 to 3.15.2 (`f56d495`; dialect specification
v0.4, `622c56f`), the newest stable release at the time (3.15.0 shipped on 2026-10-09; 3.16 was at
alpha 1). This report records what was measured, so the move can be reviewed and the next one
repeated (review 2026-11-01, astra-low-02; [review log](../reviews/review-log.md) RL-40, RL-47).

Both oracle outputs are kept in git. The 3.14.8 corpus is the expectation set of `e3c20a6`: it
was recorded on 3.13.18, and a fresh recording on 3.14.8 in the pinned image gave identical
observables for all 23 cases. The 3.15.2 corpus is `f56d495` and later.

| Dev dependencies | pytest 9.2.0, hypothesis 6.170.14, ruff 0.17.3, mypy 2.4.1, z3-solver 5.3.3.0 | the same versions; cp315 wheels for mypy and librt |
| Compiler host | Python >= 3.13 | `==3.15.*` (L0 is the host `ast`; `frontend.check_host_grammar`) |

With no code changes, the suite passed on 3.15.2: 20/20 tests, the model self-check on seeds 1, 2,
3 and 20261031, the slice 4/4, and the int differential with 0 mismatches.

## Conformance corpus

| Case | 3.14.8 | 3.15.2 | Classification |
| --- | --- | --- | --- |
| C-3-06 | `del c.x` of a missing attribute: `AttributeError.name` is `None` | `name` is `'x'` | CPython 3.15 change; `name` is a structured payload (D-08 keeps it observable) |
| C-9-02 | a callback-less weak reference to a resurrected cyclic object is dead | it is alive | CPython 3.15 change to the cyclic collector; spec section 9 rewritten, C-9-07 added |
| other 21 | identical | identical | |

Both changes already appear in 3.15.0 and in none of 3.14.8 or 3.14.10, so they are 3.15
semantics, not bug fixes backported into 3.14. The cyclic sequence, measured with `gc.collect()`:

| Step | 3.14 | 3.15 |
| --- | --- | --- |
| 1 | every weak reference cleared; callbacks run | only weak references with callbacks cleared; callbacks run |
| 2 | finalisers run | finalisers run; a callback-less weak reference still resolves inside them |
| 3 | a resurrected object lives on with dead weak references | it keeps its callback-less weak references; the rest are cleared when it is freed |

## Language and library changes that reach the dialect

| Change | Effect on Bella | Where |
| --- | --- | --- |
| PEP 810 lazy imports; `ast.Import` and `ast.ImportFrom` gain `is_lazy` (not in What's New) | 28 stdlib files use `lazy import`, 11 of them phase-1 modules, so the semantics are phase-1 work; the frontend refuses `lazy import` by name until it exists | spec sections 3, 7, 8; TODO task 1 |
| PEP 798 unpacking in comprehensions | No stdlib module uses it: \[P2+\], refused by name | spec section 3 |
| PEP 814 `frozendict`, PEP 661 `sentinel` | New builtins with stated commitments | spec sections 3, 6 |
| PEP 686 UTF-8 mode by default | D-15 narrows; CPython 3.15 still honours `PYTHONUTF8=0`, `PYTHONIOENCODING` and `encoding="locale"` (measured) | spec section 11 |
| PEP 799 `profiling` | Excluded with the other profilers (E-03) | spec sections 4, 7; `manifest.toml` |
| PEP 829 `.start` files | Ignored with `.pth` and `site` (D-18) | spec sections 8, 11 |
| PEP 803 `abi3t` | An option for the island's bridge; the version-specific bridge stays the baseline | design sections 10, 13 |
| Stricter AST constructors | All five desugarings compile under `-W error` and match the source | review log RL-13 |
| Incremental GC reverted (3.14.5+, 3.15) | No change: the design never assumed it | |

## Process for the next move

The pin moves only by a dialect-specification revision, never by floating to "latest". For a
patch release (3.15.x) or a minor one:

1. Pin the new uv release that selects the build, and update `.python-version`, `bella.toml`,
   `manifest.toml` and the Dockerfile.
2. Record the corpus on both versions and classify every observable difference against CPython's
   release notes before accepting the new expectations; add a case for each new behaviour.
3. Recompute the closure and review the differences in imports, not only in module names.
4. `uv lock`, then run `make check` on the host and in the image.
5. Revise the specification (pin, affected sections, revision log) and write a report like this one.
