## R20-01 — P1: Background threads escape dry-run confinement during artifact-saving window and execute host mutations during build

**Location:** `pipeline/staging/dryrun.py:255` (`_confine`) and lines 500–530 (`main`)

**Mechanism:**
In `pipeline/staging/dryrun.py`, confinement relies on a global integer flag `_own_writes`:
```python
_own_writes = 0

def _confine(event: str, args: tuple[Any, ...]) -> None:
    if _own_writes:
        return
```
When `dryrun.py` finishes staging a program's module bodies, `main()` wraps writing the build artifacts in:
```python
    global _own_writes
    _own_writes += 1                             # line 500
    with open(json_tmp, "w", encoding="utf-8") as f:
        json.dump(artefact, f, indent=1)
        f.write("\n")
    with open(binary_tmp, "wb") as binary:
        marshal.dump(...)
    os.replace(binary_tmp, args.binary)
    os.replace(json_tmp, args.out)
    _own_writes -= 1                             # line 530
```
Because `_own_writes` is an unconfined global counter rather than verifying that the write event is issued by `_MAIN_THREAD` targeting specifically `args.out` or `args.binary` (and their `.tmp` filenames), any background thread spawned by a program module body can retry mutating operations in a tight loop. As soon as `main()` enters `_own_writes += 1` to dump JSON and marshal data, `_confine()` returns immediately for all threads.

Consequently, running `pipeline/build.py prog.py` alone (build time only, without `--run`) allows background threads to execute arbitrary effect operations (file creation, writing, deletion, subprocess spawning, socket communication) directly against the build host filesystem outside `build/`.

**Reproducer:** Saved as `review-r20/test_window.py`:

```python
exec("pass")
import threading, time, os

def evil():
    # Loop until we successfully write
    for _ in range(1000):
        try:
            with open("/tmp/evil_window_escape.txt", "w") as f:
                f.write("escaped through _own_writes!\n")
            break
        except BaseException:
            time.sleep(0.001)

t = threading.Thread(target=evil)
t.daemon = True
t.start()
time.sleep(0.02)
```

Ensure `/tmp/evil_window_escape.txt` does not exist prior to testing:
```sh
rm -f /tmp/evil_window_escape.txt
BELLA_JOBS=8 uv run python pipeline/build.py review-r20/test_window.py
ls -l /tmp/evil_window_escape.txt
```

**CPython output**, `uv run python review-r20/test_window.py`:
Exits 0 and creates the file at run time.

**Bella build output** (compilation only, without `--run`):
```text
/home/nathan/workspaces/nth/bella-r20/build/compiled/test_window-1a05d15ff6b23ac4/test_window
```
File created on host at build time:
```text
-rw-r--r-- 1 nathan nathan 29 Nov 10 19:24 /tmp/evil_window_escape.txt
```
Contents:
```text

```

**Recommendation:** Confinement check in `_confine` should only permit writes originating from `_thread.get_ident() == _MAIN_THREAD` where the path being opened or replaced is strictly within the expected staging artifact paths.

## R20-02 — P1: os.mkfifo and os.mknod in module bodies escape confinement and create host filesystem nodes during build

**Location:** `pipeline/staging/dryrun.py:198–205` (`_EFFECTS`)

**Mechanism:**
In CPython 3.15, `posix_mkfifo` and `posix_mknod` do not call `PySys_Audit()` and do not generate audit events. Neither `os.mkfifo` nor `os.mknod` is interceptable via `sys.addaudithook`, nor are they shadowed or blocked before staging module bodies.

When a module body invokes `os.mkfifo()` or `os.mknod()` during import, the system call executes unconditionally in the dry-run process at build time, altering the host filesystem outside `build/`.

**Reproducer:** Saved as `review-r20/fifo.py`:

```python
import os
exec('x = 1')
os.mkfifo('/tmp/bella-r20-created-fifo')
print('created')
```

Ensure `/tmp/bella-r20-created-fifo` does not exist prior to testing:
```sh
rm -f /tmp/bella-r20-created-fifo
BELLA_JOBS=8 uv run python pipeline/build.py review-r20/fifo.py
ls -l /tmp/bella-r20-created-fifo
```

**CPython output**, `uv run python review-r20/fifo.py`:
```text
created
```

**Bella build output** (compilation only, without `--run`):
```text
/home/nathan/workspaces/nth/bella-r20/build/compiled/fifo-e2ea773b0a7019ae/fifo
```
Host state immediately following build:
```text
prw-r--r-- 1 nathan nathan 0 Nov 10 19:24 /tmp/bella-r20-created-fifo
```
A named pipe was created on the build host outside `build/` during `build.py` alone.

**Recommendation:** In `dryrun.py`, intercept un-audited mutating POSIX functions (`os.mkfifo`, `os.mknod`, `posix.mkfifo`, `posix.mknod`) by wrapping or replacing them on `os` and `posix` with functions that call `_confine()` directly when `_started` is active.

## R20-03 — P2: Read-only lock query os.lockf(fd, os.F_TEST, ...) wrongly refused by dry-run confinement, aborting staging with a spurious note

**Location:** `pipeline/staging/dryrun.py:199` (`_EFFECTS`)

**Mechanism:**
`_EFFECTS` unconditionally includes `"os.lockf"`.
However, `os.lockf(fd, cmd, len)` supports four commands: `os.F_LOCK`, `os.F_TLOCK`, `os.F_ULOCK`, and `os.F_TEST`.
`os.lockf(fd, os.F_TEST, ...)` does not establish, remove, or modify any file lock; it is an enquiry that solely tests whether section locks exist from other processes (querying `F_GETLK`). It has no mutating effect on the filesystem or process state.

By including `"os.lockf"` unconditionally in `_EFFECTS`, `dryrun.py` treats `os.F_TEST` queries as mutating effects, emits a build note (`bella: note: ...: the dry run of this module body ended here, at os.lockf(...)`), and halts the module body prematurely. Consequently, subsequent definition-time code (dataclasses, TypedDicts, functions) is not staged, causing the compiled binary to stop unexpectedly at run time.

**Reproducer:** Saved as `review-r20/test_lockf_read.py`:

```python
exec("pass")
import os

f = open(__file__, "r")
try:
    os.lockf(f.fileno(), os.F_TEST, 0)
    print("lockf test succeeded")
except BaseException as e:
    print("lockf test failed:", type(e).__name__, e)
f.close()
```

Run command:
```sh
uv run python review-r20/test_lockf_read.py
BELLA_JOBS=8 uv run python pipeline/build.py --run review-r20/test_lockf_read.py
```

**CPython output:**
```text
lockf test succeeded
```
Exits 0.

**Bella build and run output:**
```text
bella: note: /home/nathan/workspaces/nth/bella-r20/review-r20/test_lockf_read.py:6: the dry run of this module body ended here, at os.lockf(3): a module body's effects on the world are not performed at build time. Definition-time code the body reaches after this line is not staged and stops the program by name (docs/staging.md)
bella: not implemented: os.lockf (CPython has it; the runtime does not yet)
```
Exits with status 70.

**Recommendation:** In `dryrun.py:277`, distinguish `event == "os.lockf"` by checking `args[1]`: if `args[1] == os.F_TEST`, do not refuse the call since it is a pure read enquiry.

## R20-04 — P2: shutil.chown, signal.pthread_kill, and webbrowser.open missing from _EFFECTS

**Location:** `pipeline/staging/dryrun.py:198–205` (`_EFFECTS`)

**Mechanism:**
Python's standard library and CPython runtime emit distinct audit events for host-mutating actions that are currently omitted from `_EFFECTS`:
- `shutil.chown` emits `sys.audit("shutil.chown", path, user, group)`
- `signal.pthread_kill` emits `PySys_Audit("signal.pthread_kill", ...)`
- `webbrowser.open` emits `sys.audit("webbrowser.open", url)`

Because `signal.pthread_kill` is absent from `_EFFECTS`, a background thread or module body can signal or terminate other threads during staging without being stopped. For `shutil.chown`, if arguments are invalid or if user lookup fails before reaching `os.chown`, the operation is not recognized as a confined attempt under `_confined`.

**Reproducer:** Saved as `review-r20/test_missing_effects.py`:

```python
exec("pass")
import sys

try:
    sys.audit("signal.pthread_kill", 0, 0)
    print("pthread_kill not in _EFFECTS")
except BaseException as e:
    print("confined:", type(e).__name__, e)
```

Run build:
```sh
BELLA_JOBS=8 uv run python pipeline/build.py review-r20/test_missing_effects.py
```

**CPython output:**
`pthread_kill not in _EFFECTS`

**Bella build output:**
```text
/home/nathan/workspaces/nth/bella-r20/build/compiled/test_missing_effects-f45c6b22d2080d66/test_missing_effects
```
Build exits 0 without emitting any confinement note. In contrast, all audit events in `_EFFECTS` produce a diagnostic build note.

**Recommendation:** Add `"shutil.chown"`, `"signal.pthread_kill"`, and `"webbrowser.open"` to `_EFFECTS`.

## R20-05 — P3: os._exit() in dryrun.py bypasses stream flushing when sys.stdout/sys.stderr are wrapped and drops diagnostic traces

**Location:** `pipeline/staging/dryrun.py:544–550`

**Mechanism:**
At the end of `dryrun.py`, the process exits immediately via `os._exit(status)`:
```python
    for stream in (sys.__stdout__, sys.__stderr__):
        try:
            if stream is not None:
                stream.flush()
        except Exception:  # noqa: BLE001, S110
            pass
    os._exit(status)
```
Lines 544–549 only flush `sys.__stdout__` and `sys.__stderr__`. When `sys.stdout` or `sys.stderr` is wrapped or redirected (for example by test runners, diagnostic wrappers, or pipeline tools), any buffered diagnostic output or warnings residing in `sys.stdout` or `sys.stderr` are never flushed to the underlying file descriptors and are lost when `os._exit()` terminates the process without invoking `Py_FinalizeEx()` or `atexit`.

**Recommendation:** Flush `sys.stdout` and `sys.stderr` in addition to `sys.__stdout__` and `sys.__stderr__` before invoking `os._exit(status)`.
